# REQUIREMENTS CHECKLIST (Notes + AI Analysis)

Updated: 2026-05-11
Status: In progress (production features + prototype AI analysis flow)

## 1. Notes data is user-scoped

Status: Implemented

Verification:
- Notes are filtered by authenticated user id in notes page logic.
- API routes use authenticated user from session where applicable.
- Data isolation is enforced by database policies (RLS) on Supabase side.

## 2. Notes history (full + mini notes)

Status: Implemented

Verification:
- UI separates full notes (mood/sleep) and quick mini notes.
- History is rendered in date order with editing and deletion actions.

## 3. Separate block for mini notes

Status: Implemented

Verification:
- Mini notes are displayed in a dedicated section.
- Quick add/remove interactions are available.

## 4. Mood and sleep charts

Status: Implemented

Verification:
- Line charts are rendered for mood and sleep trends.
- Tooltips/axes are present for quick visual analysis.

## 5. Basic analytics (average mood/sleep)

Status: Implemented

Verification:
- Average mood and average sleep are computed on client side.
- Totals for full and mini notes are displayed.

## 6. AI analysis integration for notes comments

Status: Partially implemented

What is implemented:
- Endpoint POST /api/notes/analyze validates session user.
- Endpoint builds structured analysis prompt from notes inputs.
- Request metadata (prompt/comments count/time) is saved to database.

What is not yet implemented in this endpoint:
- No direct call to external AI model inside /api/notes/analyze.
- No persisted final AI response generated by model in this route.

## 7. Security checks

Status: Implemented with recent hardening

Verification:
- /api/telegram/deep-link now requires authenticated session.
- Requested userId must match current authenticated user (IDOR protection).

## 8. Documentation consistency

Status: Needs continuous maintenance

Current notes:
- Legacy references to docs/NOTES_AI_ANALYSIS.md and docs/NOTES_EXAMPLES.js were removed from this checklist because these files are not present in repository.
- Keep README and diploma docs aligned with actual API behavior (especially AI analysis routes and debug-only flows).

## 9. Known limitations (must be stated in diploma/demo)

- Local AI infrastructure dependency (LM Studio availability/config).
- Some UI lint issues may remain outside core API path.
- Parts of AI diagnostic flow are prototype-level and should be labeled as such.
- System is not a clinical decision support tool.

## 10. Pre-demo quick checks

- Environment variables are set (Supabase + LM Studio + RAG flags).
- LM Studio server is running and model names match config.
- Key scenarios pass:
  - chat happy path,
  - notes save/read,
  - POST /api/notes/analyze preparation flow,
  - profile + telegram linking flow.
