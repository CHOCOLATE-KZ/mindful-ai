# MindfulAI — Изменения, важные для дипломной работы (май 2026)

> **Синхронизация с Word Version3:** см. [`DIPLOMA_VERSION3_SYNC.md`](./DIPLOMA_VERSION3_SYNC.md) — полный список убранного/добавленного и правки для пояснительной записки.

## Назначение документа

Этот файл фиксирует ключевые изменения проекта с момента предыдущей версии описания. Фокус: только то, что важно для дипломной работы (архитектура, ИИ-логика, продуктовый функционал, безопасность, пользовательский опыт, техдолг/ограничения).

## 1) Главный итог периода

Проект перешел от базового чат-бота к более зрелой платформе с:
- многоуровневым AI-pipeline (intent routing, safety, mode-based prompting, post-validation),
- расширенной персонализацией по данным пользователя при privacy-consent,
- более полной аналитикой и AI-отчетностью,
- существенно обновленным UX чата (боковая навигация, **заметки чата**, voice/session flow),
- пересборкой документации: удалены устаревшие руководства, добавлены актуальные handoff-файлы.

## 2) Изменения AI и backend-логики

### 2.1. Новый полный pipeline в `POST /api/chat`

Текущая обработка сообщения включает:
1. Предобработку и intent-флаги (greeting, gratitude, positive/negative/neutral).
2. Safety pre-check:
   - hard-block паттерны для явно опасных/незаконных инструкций,
   - исключение для терапевтического контекста зависимости.
3. Crisis detection по триггерам суицидального/самоповреждающего контента.
4. Сбор персонального контекста (profile + notes + user settings) при разрешении data sharing.
5. Классификацию режима ответа: `LISTENING`, `ANALYSIS`, `GUIDANCE`.
6. Подключение RAG (если включено и запрос достаточной длины).
7. Генерацию ответа через LM Studio.
8. Post-validation и sanitation (очистка артефактов, контроль длины/вопросов, anti-duplication, affect consistency).

Практическая ценность для диплома: это уже не "один prompt к LLM", а управляемая цепочка принятия решений.

### 2.2. Prompt-engineering перешел на режимную модель

В системном промпте зафиксированы:
- отдельные инструкции и шаблоны ответа для трех режимов,
- anti-duplication правила,
- контекстный safety intent-filter,
- кризисный протокол,
- ограничение домена (психологическая поддержка).

Это упрощает формальное описание в главе архитектуры: можно явно показать policy-layer + response-layer.

### 2.3. Пост-валидация ответа как отдельный слой качества

Добавлен модуль validator/sanitizer, который:
- удаляет статистические/шумовые хвосты и тех. заголовки,
- ограничивает ответ по mode-specific лимитам,
- сокращает дубляж и лишние вопросы,
- корректирует tone mismatch (например, негативизация позитивного check-in).

Ценность: повышение стабильности и предсказуемости ответов без дообучения модели.

### 2.4. AI-аналитика профиля и недели усилена

В `POST /api/ai/profile-report` расширены:
- derived metrics (тренды, сигналы, агрегаты),
- risk/resource индексы,
- confidence/evidence блок,
- структурированный выход для аналитического интерфейса.

История отчетов поддерживается через `GET /api/ai/profile-report`.

## 3) RAG и база знаний

Текущий RAG-контур:
- embeddings + semantic search (через RPC),
- fallback на keyword-поиск,
- управляемость через env-флаги (`ENABLE_PSYCHOLOGY_RAG`, `RAG_LIMIT`, `RAG_MIN_QUERY_LENGTH`).

Для диплома важно подчеркнуть, что retrieval теперь configurable и отказоустойчивый (graceful degradation при проблемах embedding-сервиса).

## 4) Клиентская часть: ключевые изменения UX/архитектуры

### 4.1. Чат как отдельная UX-зона

Добавлены/обновлены:
- отдельный левый navigation rail для chat-сценария,
- модалка **заметок чата** (`ChatNotesModal`, таблица `chat_notes`) — темы для диалога, без привязки к сообщениям,
- вставка выбранной заметки в поле ввода («Хочу обсудить: …»),
- обновленный flow composer/conversation/header/messages,
- обновленный scroll behavior.

### 4.2. Voice и session сценарии

Улучшена логика voice-потока:
- устойчивый state machine (`idle/listening/thinking/speaking`),
- синхронизация speech recognition и TTS,
- явная обработка secure-context ограничений (HTTPS/localhost).

Session-mode дополнен persistence-настройкой подтверждения через localStorage.

### 4.3. Layout и навигация

Вынесен `LayoutContent`:
- для chat-страницы применяется отдельная компоновка без глобального navbar,
- для остальных страниц сохранен общий navbar + top spacing.

Это важное архитектурное разделение публичного/приложенческого UX.

### 4.4. Экспорт данных пользователя

В chat-flow добавлен удобный экспорт:
- JSON (машиночитаемый),
- PDF (печатный отчет через print-template).

Для диплома это усиливает блок про data portability и пользовательский контроль данных.

## 5) Эмоции и мультимодальный контекст

EmotionTracker переработан:
- динамический импорт `face-api.js`,
- корректный lifecycle камеры и освобождение stream tracks,
- периодическое определение доминирующей эмоции и отправка в API.

На backend присутствует `api/emotion` (прототипное in-memory хранение эмоций в `globalThis.userEmotions`).

Важно для диплома: это рабочий прототип мультимодального сигнала, но еще не production-grade хранилище.

## 8) Что важно явно написать в дипломе

Рекомендуемые формулировки:

1. "Система реализует многоуровневую архитектуру генерации ответа: pre-filtering, intent-aware mode selection, retrieval augmentation, post-generation validation."
2. "Персонализация контролируется пользовательским согласием и может быть отключена в privacy-настройках."
3. "RAG-подсистема поддерживает деградацию до keyword-поиска при недоступности embedding-пути."
4. "Мультимодальный модуль эмоций интегрирован на уровне прототипа и используется как дополнительный контекст, а не как диагностический инструмент."
5. "Система ориентирована на психологическую поддержку и не выполняет медицинскую диагностику."

## 9) Ограничения текущей версии (для честного раздела "Недостатки")

1. `api/emotion` использует in-memory storage и не обеспечивает долговременную/распределенную консистентность.
2. Качество RAG зависит от полноты таблицы `psychology_knowledge` и доступности embedding endpoint.
3. Safety-правила существенно снижают риск нежелательных ответов, но не заменяют клинический надзор специалиста.
4. Часть UX-поведения завязана на browser capabilities (speech APIs, secure context).

---

## 10) Краткий вывод для главы диплома

За рассматриваемый период MindfulAI эволюционировал в более устойчивую и объяснимую AI-систему: улучшены контроль ответов, безопасность, персонализация, аналитика и пользовательский интерфейс. С инженерной точки зрения проект приблизился к production-паттернам (слоистый pipeline, graceful fallback, модульный UI), сохранив при этом ограничения прототипа в отдельных подсистемах (emotion storage, зависимость от локальной AI-инфраструктуры).
